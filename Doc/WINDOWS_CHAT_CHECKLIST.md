# Проверка AI Chat в packaged Windows-сборке

Этот сценарий закрывает текущую границу Этапа 4: реальный локальный Ollama, bundled Python,
контекст редактора, предложение замены, построчный diff и lifecycle дочерних процессов.
Проверку нужно выполнять на Windows 10/11 с установленной packaged-сборкой AutoCoder.

## Фактический статус на 28 августа 2026

- Основной сценарий контекста, proposal/diff, Reject, Apply, Save и backup: **PASS**.
- Lifecycle owned Ollama, external Ollama и shutdown во время запроса: **PASS**.
- Отсутствующий `ollama.exe`: **не проверено отдельно**.
- Отсутствующая модель: **не проверено отдельно**.
- HTTP 503 readiness: **не проверено отдельно**.

Checklist сохраняется для воспроизведения уже подтверждённого основного сценария и будущих
диагностических прогонов. Непроверенные негативные сценарии не отменяют подтверждённый
результат основного packaged Windows-сценария.

## Подготовка

1. Заранее установить Ollama и модель `qwen2.5-coder:7b`.
2. Создать тестовый проект с UTF-8 файлом `chat-check.txt`:

   ```text
   Первая строка
   Вторая строка
   Третья строка
   ```

3. Отключить сеть. Не удалять модель после отключения сети.
4. Завершить все процессы Ollama и запустить установленный AutoCoder.
5. Открыть тестовый проект и `chat-check.txt`.

Перед проверкой зафиксировать среду в PowerShell, чтобы результат можно было повторить:

```powershell
Get-ComputerInfo | Select-Object WindowsProductName, WindowsVersion, OsBuildNumber
Get-FileHash "<путь к установленному autocoder.exe>" -Algorithm SHA256
ollama list
```

Не помещать в отчёт имена пользователя, полный путь к домашнему каталогу и другие
персональные данные. Для каждого раздела ниже использовать один из статусов: `PASS`,
`FAIL` или `BLOCKED`. `BLOCKED` означает, что проверка не запускалась из-за конкретного
ограничения среды, и не считается успешным результатом.

## Основной сценарий

1. Спросить: `Какой файл открыт и что находится во второй строке?`
   - Ответ должен назвать `chat-check.txt` и `Вторая строка`.
   - Во время запроса не должно появляться консольное окно Python или Ollama.
2. Выделить `Третья строка` и спросить: `Что сейчас выделено?`
   - Ответ должен опираться на выделение.
3. Снять выделение и повторить вопрос.
   - Новый запрос не должен получать ответ предыдущей ветки как историю.
4. Изменить, но не сохранять вторую строку на `Вторая строка изменена`, и спросить о ней.
   - Ответ должен учитывать несохранённый текст, а не содержимое на диске.
5. Попросить заменить открытый файл целиком, сохранив первую строку, изменив вторую и
   удалив третью.
   - AutoCoder должен показать предложение только для открытого файла.
   - Diff должен показывать неизменённую первую строку, удалённые строки до добавленных
     и корректные старые/новые номера строк.
6. Отклонить первое предложение и убедиться, что файл не изменился.
7. Повторить запрос, принять предложение и сохранить файл.
   - Перед записью должна появиться backup-копия с исходным содержимым.
   - На диске должно оказаться ровно принятое содержимое.

## Lifecycle Ollama

1. Во время двух последовательных запросов должен существовать один запущенный
   AutoCoder процесс `ollama.exe`; повторного запуска быть не должно.
2. После обычного закрытия AutoCoder принадлежащие ему `ollama.exe`, `llama-server`,
   Python и helper-процессы должны исчезнуть.
3. Повторить запуск с заранее запущенным внешним Ollama.
   - AutoCoder должен использовать его, не создавая второй процесс.
   - После закрытия AutoCoder внешний Ollama должен продолжить работу.
4. Во время запроса с принадлежащим AutoCoder Ollama закрыть приложение.
   - После закрытия не должны остаться принадлежащие приложению дочерние процессы.

## Отдельные ошибки

После каждого подпункта вернуть изменённые файлы на место.

1. Временно переименовать `ollama.exe`: UI должен явно сообщить, что Ollama не найден.
2. Временно переименовать каталог модели: UI должен отдельно сообщить, что модель
   `qwen2.5-coder:7b` не установлена.
3. Запустить сервис, который принимает TCP-соединение на endpoint Ollama, но отвечает
   HTTP 503: AutoCoder не должен считать такой endpoint готовым.

## Фиксация результата

Записать дату, версию Windows, тип сборки и результат каждого раздела в
`Doc/PROJECT_STATE.md`. При сбое сохранить точный текст ошибки из UI, строку
`send_chat_message failed` из DevTools и `AutoCoder chat backend failed` из журнала
запуска. До успешного прохождения основного сценария не расширять File Tool на создание
или удаление файлов.

Скопировать в `Doc/PROJECT_STATE.md` заполненный блок:

```text
Дата и время (с часовым поясом):
Windows edition/version/build:
AutoCoder version и SHA-256:
Ollama version:
Модель из `ollama list`:
Сеть физически отключена: PASS / FAIL / BLOCKED
Основной сценарий: PASS / FAIL / BLOCKED
Lifecycle owned Ollama: PASS / FAIL / BLOCKED
Lifecycle external Ollama: PASS / FAIL / BLOCKED
Закрытие во время запроса: PASS / FAIL / BLOCKED
Ошибка отсутствующего executable: PASS / FAIL / BLOCKED
Ошибка отсутствующей модели: PASS / FAIL / BLOCKED
HTTP 503 не принят за readiness: PASS / FAIL / BLOCKED
Backup (путь и проверенное исходное содержимое):
Точная ошибка и диагностические строки при FAIL:
Итог: PASS / FAIL / BLOCKED
```

Итоговый `PASS` допустим только тогда, когда все строки проверки имеют статус `PASS`.
Если хотя бы одна строка имеет статус `FAIL` или `BLOCKED`, зафиксировать её как следующий
конкретный шаг и не объявлять Windows-сценарий подтверждённым.
