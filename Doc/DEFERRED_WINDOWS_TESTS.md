# Отложенные ручные проверки Windows

Здесь хранится только минимальный список проверок, которые нельзя достаточно надёжно закрыть
кодом, review diff или автоматическими regression/integration/unit-тестами, но остаточный риск
которых не мешает безопасно и достоверно продолжать разработку. Отнесение изменения к Save,
файловой безопасности, backup/restore, удалению или потенциальной потере данных само по себе не
требует немедленного прогона. Некритические проверки выполняются единым acceptance-прогоном на
ближайшем барьере 50%, 60%, 70%, 80%, 90% или 100%.

Перед прогоном список необходимо ревизовать: исключить уже доказанное автоматикой, удалить или
пометить `obsolete` неактуальное, объединить пересечения и оставить минимальный набор реально
необходимых проверок. После ревизии пользователю выдаётся один объединённый copy-paste-ready
сценарий.

Stale Save из PR #55 сюда не входит: пользователь уже проверил его в packaged Windows, статус
**PASS** зафиксирован в `PROJECT_STATE.md` и `WINDOWS_CHAT_CHECKLIST.md`.

## 50% — диагностика Tauri в packaged UI

### PR #53 — блокировка смены проекта активной Terminal-командой

- **Изменение / PR:** PR #53, отображение backend-причины ошибки открытия проекта.
- **Проверить вручную:** при активной долгой Terminal-команде попытаться открыть другой проект;
  Project Explorer должен показать точную backend-диагностику рядом с локализованным сообщением.
- **Почему автоматизации недостаточно:** component regression подтверждает рендер переданной строки,
  но не фактическую форму ошибки, которую packaged Tauri доставляет frontend на Windows.
- **Барьер:** 50%.
- **Статус:** `pending`.
- **Минимальный сценарий:** включить этот пункт в объединённый сценарий барьера; отдельный прогон PR
  не требуется. Запустить долгую команду, выбрать другой проект и сохранить точный текст ошибки.

### PR #54 — диагностика файловых операций и Backup Manager

- **Изменение / PR:** PR #54, сохранение backend-диагностики для read/save/create/delete,
  чтения списка backup и restore.
- **Проверить вручную:** вызвать одну безопасную stale-state ошибку восстановления backup и убедиться,
  что диалог показывает не только общее сообщение, но и точную backend-причину.
- **Почему автоматизации недостаточно:** unit-тест подтверждает форматирование строковых и `Error`
  значений, однако форму rejected IPC value и его отображение в установленном Windows WebView
  надёжно подтверждает только packaged-прогон.
- **Барьер:** 50%.
- **Статус:** `pending`.
- **Минимальный сценарий:** открыть Backup Manager, выбрать backup, изменить соответствующий файл
  внешним редактором и нажать «Восстановить»; записать точный текст, не включая персональные пути.

### Atomic Save — Windows replacement и recovery

- **Изменение / PR:** ранее реализованный Windows atomic replacement path.
- **Проверить вручную:** только оставшиеся после ревизии барьера platform-specific ветви replacement
  и recovery; исходный воспроизводимый сценарий сохранён в `WINDOWS_CHAT_CHECKLIST.md`.
- **Почему автоматизации недостаточно:** Linux-проверки не исполняют Windows API replacement и
  диагностические ветви системных кодов 1175–1177 в установленном приложении.
- **Почему не критично немедленно:** код и автоматические regressions уже позволяют безопасно
  продолжать разработку; один только риск файловой операции не делает ручной тест критическим.
- **Барьер:** 50%.
- **Статус:** `pending review`: перед прогоном исключить доказанные автоматикой пункты и объединить
  остаток с проверками Tauri-диагностики в один сценарий.
