# AutoCoder — AGENTS.md (Инструкции для ИИ-ассистентов)

Этот документ содержит свод правил, стандартов и инструкций для искусственного интеллекта (LLM / Codex / AI-ассистентов), работающих над разработкой среды AutoCoder. 

Перед началом выполнения любой задачи ИИ-ассистент обязан ознакомиться с этим файлом, а также с `PROJECT_MEMORY.md` и `PROJECT_STATE.md`.

---

## 1. Роль ИИ в проекте
ИИ-ассистент является основным разработчиком (исполнителем), работающим под руководством Илья (владельца проекта). 
Главный принцип работы — **последовательность, точность и минимализм**. Мы создаем MVP как можно быстрее, не усложняя архитектуру сверх меры, но оставляя её расширяемой.

---

## 2. Стек технологий и архитектура
При предложении решений, написании кода или установке библиотек ИИ должен строго придерживаться выбранного стека:
- **Frontend:** React + Tauri (TypeScript)
- **Backend:** Python (для оркестрации, локального анализа и работы с инструментами)
- **Редактор:** Monaco Editor
- **База данных:** SQLite
- **Локальная LLM:** Ollama (для работы в офлайн-режиме)
- **Целевая ОС:** Windows 10/11

---

## 3. Правила изменения файлов и написания кода
1. **Точечные изменения:** Предпочитать локальные, точечные изменения (`replace_in_file`) вместо полной перезаписи файлов, если только файл не создается с нуля или не переписывается полностью.
2. **Лицензионная чистота:** Использовать только сторонние библиотеки с permissive-лицензиями (MIT, BSD, Apache-2.0). Категорически избегать GPL/AGPL в зависимостях проекта.
3. **Безопасность секретов:**
   - Никогда не коммитить секреты, токены и API-ключи (например, `OPENAI_API_KEY`, `GOOGLE_API_KEY`, `GITHUB_TOKEN`).
   - Все секреты должны находиться исключительно в `.env` файле, который добавлен в `.gitignore`.
4. **Резервное копирование:** Перед внесением изменений в критические файлы AutoCoder должен делать их резервные копии (в рамках внутренней логики приложения). При работе самого ИИ в репозитории следует опираться на коммиты Git как на средство отката.
5. **COMSOL Multiphysics 6.4.429:**
   - При работе со специализацией COMSOL (Java API, Java Shell, Methods) категорически запрещено «галлюцинировать» или придумывать методы API.
   - Источником истины является исключительно официальная документация COMSOL, примеры и код пользователя. Если информации недостаточно, ИИ должен прямо сообщить о неопределенности.

---

## 4. Git & GitHub Workflow
1. **Основная ветка:** Все изменения на данном этапе вносятся напрямую в ветку `main`, так как разработка ведется одним человеком. Сложная branch protection и pull request rulesets пока не используются для ускорения работы.
2. **Атомарные коммиты:** Изменения должны коммититься небольшими логическими порциями. Каждому коммиту должно соответствовать ясное сообщение на русском или английском языке (например: `feat: add database initial schema` или `docs: create AGENTS.md`).
3. **Собственные утилиты:** AutoCoder не должен зависеть от наличия Git в системе пользователя для выполнения базовых операций (чтение, запись, бэкап).

---

## 5. Работа с проектной памятью (`Doc/`)
ИИ-ассистент обязан поддерживать актуальность файлов в папке `Doc/`:
1. **`PROJECT_MEMORY.md`** — редактируется редко, только при изменении глобальных архитектурных решений, стека технологий или долгосрочных целей.
2. **`PROJECT_STATE.md`** — обновляется регулярно. После выполнения значимой задачи или изменения этапа разработки ИИ должен зафиксировать:
   - дату изменения;
   - что было фактически сделано и проверено;
   - текущую нерешенную проблему или следующий шаг.

---

## 6. Алгоритм решения задач ИИ
1. **Анализ:** Прочитать текущую задачу, сопоставить её с `PROJECT_STATE.md` и файлами проекта.
2. **Планирование:** Предложить минимальное и самое простое рабочее решение. Избегать преждевременной оптимизации и добавления не затребованных функций.
3. **Реализация:** Написать код, соответствующий стандартам проекта.
4. **Тестирование:** Проверить работоспособность (запустить тесты, проверить синтаксис, убедиться в отсутствии регрессий).
5. **Фиксация результатов:** Закоммитить изменения в Git, обновить `PROJECT_STATE.md` и передать результат Илье.
